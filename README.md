### 🚀 Featured projects

Ranked in the order I'd recommend pinning them — leads with the most
complete/production-shaped systems, ends with the coursework-style projects
that show engineering fundamentals.

**1. [AI Recruiter System](https://github.com/melfouly903/AI-Recruiter-System)**
End-to-end recruitment platform: an LLM agent evaluates candidates against
skills/projects/experience, an AI scheduling agent books interviews within
business rules, and an automation agent sends the invite email — all
surfaced on a real-time React/Recharts HR dashboard.
`React` `Vite` `Tailwind` `Supabase/Postgres` `n8n` `LLM (OpenRouter/Gemini)`
— *Why it's #1:* it's the clearest evidence of "AI agent embedded in a real
product," with a UI a non-technical HR user could actually use.

**2. [AI Hotel Booking Assistant](https://github.com/melfouly903/Azure-Hotel_booking_system)**
A Telegram-native booking assistant: a Gemini-powered agent with conversation memory, a Supabase/pgvector RAG knowledge base for hotel FAQs, and two tool-workflows it calls autonomously to check live availability and create a confirmed booking, capped off with an automated Gmail confirmation.
`n8n` `Gemini` `Supabase (pgvector)` `RAG` `Telegram API` `Gmail API`
— *Why it's #2:* different stack from #1 (workflow-orchestration vs. custom
app), so together they show you can build agents both ways.

**3. [Second-Hand Mobile Price Analyzer](https://github.com/melfouly903/Second-Hand-Mobile-Price-Analyzer)**

`CNN` `ViT` `LSTM/GRU` `Arabic NLP` `Web Scraping`

`Python` `TensorFlow/Keras` `CNN` `Object Detection`

**5. [Student Management System](https://github.com/melfouly903/Backend_project)**

### 💭 Engineering philosophy

I'd rather ship an AI feature that's wired into a real workflow — a
database, a scheduler, an inbox — than a model that only works inside a
notebook. Most of my projects follow the same shape: define the business
process first, then decide where an LLM or a classical model actually earns
its place in it.
